- WhatsApp can run through the external QR linked-device bridge in `whatsapp-gateway/` (Baileys, deployed separately): when `WA_GATEWAY_URL`/`WA_GATEWAY_API_KEY` exist, `sendText` uses it and `/api/public/whatsapp-qr` (shared-key auth) feeds the same `handleIncoming`; `fromMe` messages pause the bot for that chat. Workers cannot hold the persistent WhatsApp socket.
- The bridge runs Baileys 7, keeps one socket at a time (old one ended before reconnect), replies to the chat JID the customer wrote from (@lid included, persisted in chats.json) and queues sends per chat; libsignal console output is filtered because it prints private keys. This avoids the Bad MAC session thrash that left phones on "Esperando mensaje".
